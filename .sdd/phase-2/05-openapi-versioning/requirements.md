# Requirements - 05 OpenAPI and API Versioning

## Objective

Modernize active API documentation and versioning for the .NET 10 application while preserving controller routes and observable API behavior where possible.

## Scope

- Replace obsolete `Microsoft.AspNetCore.Mvc.Versioning*`.
- Remove Swashbuckle generation and legacy Swagger-specific filters.
- Generate valid OpenAPI documents for each API version.
- Expose a functional documentation UI.
- Document JWT Bearer authentication.
- Document Problem Details and rate-limit responses.
- Provide a repeatable command to generate the contract for future CI validation.
- Preserve controllers and route templates.

## Out of Scope

- No migration to Minimal APIs.
- No route redesign.
- No architectural modernization from later phases.
- No global tool or Node.js dependency.

## Acceptance Criteria

- `/openapi/v1.json` and `/openapi/v2.json` respond with valid JSON.
- `/scalar/` responds successfully in the test host.
- Versioned docs contain the existing v1 and v2 paths.
- JWT is represented as HTTP bearer with JWT format.
- Problem Details is represented as `application/problem+json`.
- `429`, `401`, and `403` are documented where applicable.
- Contract can be generated by command into `docs/openapi/`.
- Build and tests pass.
- Obsolete API Versioning and Swashbuckle packages are absent from active code.
