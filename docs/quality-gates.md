# Quality Gates

## Required Checks

Recommended branch protection checks for Phase 3:

| Check name | Source | Required |
| --- | --- | --- |
| `Build, test and quality gates` | `.github/workflows/ci.yml` | yes |
| `SonarCloud Quality Gate` | `.github/workflows/ci.yml` | yes for trusted pushes and trusted pull requests |

| `Review dependency changes` | `.github/workflows/dependency-review.yml` | yes for pull requests |

SonarCloud setup, Quality Gate policy and branch protection details are documented in [docs/quality/sonarcloud.md](quality/sonarcloud.md).

dotnet build WebApiCoreSeed.slnx --configuration Release --no-restore
dotnet test tests/WebApiCoreSeed.UnitTests/WebApiCoreSeed.UnitTests.csproj --configuration Release --no-build --logger "trx;LogFileName=unit-tests.trx" --results-directory TestResults/Unit --collect:"XPlat Code Coverage" -- DataCollectionRunSettings.DataCollectors.DataCollector.Configuration.Format=cobertura,opencover "DataCollectionRunSettings.DataCollectors.DataCollector.Configuration.Exclude=[*.Test]*,[*.Tests]*,[*.UnitTests]*,[*.IntegrationTests]*" "DataCollectionRunSettings.DataCollectors.DataCollector.Configuration.ExcludeByFile=**/*.generated.cs"

## Artifacts

- `test-results`: TRX files from unit and integration test projects.
- `coverage-results`: Cobertura and OpenCover XML files generated by `coverlet.collector`.
- `openapi-contracts`: generated `docs/openapi/openapi-v*.json` files.

Artifact uploads are conditional on matching files existing. This avoids secondary upload failures when an earlier mandatory step fails before tests or OpenAPI generation creates output.

## Pull Request Contexts

| Context | Independent gates | SonarCloud | Reason |
| --- | --- | --- | --- |
| Same-repository pull request | required | required when `SONAR_TOKEN` is configured | Trusted PRs can receive repository secrets. |
| Dependabot pull request | required | skipped with an explicit notice | Dependabot PRs do not receive repository Actions secrets. |
| Fork pull request | required | skipped with an explicit notice | Fork PR code is untrusted and must not run with repository secrets. |
| Push to `main` | required | required | Trusted branch update. |

The workflow does not use `pull_request_target` for SonarCloud. Secrets are never exposed to untrusted pull request code.

## Docker Requirement

Integration tests use Testcontainers with SQL Server and Redis:

- `mcr.microsoft.com/mssql/server:2022-CU14-ubuntu-22.04`
- `redis:7.4.2-alpine`

The GitHub-hosted Ubuntu runner provides Docker. No duplicate workflow `services` are declared.

## Formatting

`dotnet format WebApiCoreSeed.slnx --verify-no-changes` is not a blocking CI gate yet because the current repository has existing whitespace debt. Keep formatting local and enable the gate only after a dedicated cleanup commit.

## Failure Behavior

CI commands run without `continue-on-error`. Restore, build, tests, OpenAPI synchronization, vulnerable package audit, CodeQL, dependency review and trusted SonarCloud Quality Gate analysis return non-zero status when their gate fails.

SonarCloud runs in a separate job from the independent repository-local gates. If SonarCloud cannot initialize, build, tests, coverage, OpenAPI validation and package checks still run in `Build, test and quality gates`. In trusted contexts, missing `SONAR_TOKEN`, scanner errors, Quality Gate failures and Quality Gate timeouts still fail `SonarCloud Quality Gate`.
